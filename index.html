Artifact One - Contact Service

Download Contact Service Artifact

Artifact Narrative

Description

My ContactService assignment was from my CS 320: Software Test Automation course. It was originally created to operate a simple CRUD (Create, Read, Update, and Delete) management system to manage a variety of contacts. This application was able to receive inputs from the user, put them through a validation system to see if they're acceptable, and add them to a single Hashmap that can be edited through CRUD methods.

Justification

I chose this artifact to be included in my ePortfolio as it was an assignment I had initially struggled with creating on Eclipse due to issues with the application itself. While the original artifact already has a simple CRUD management system, its first enhancement has many potential components in demonstrating my skills in software development with practices such as validation methods and modifying Java classes. To improve this artifact, my first enhancement was the validation logic for the Contact class by adding stronger checks for invalid or null input for all variables such as names and addresses, ensuring phone numbers contain only ten digits, and improving duplicate data prevention within the ContactService class. My second enhancement was implementing a multi-index data structure by adding additional HashMap indexes for first names, last names, and phone numbers. These indexes allow the application to retrieve contacts directly instead of searching through every stored contact.

Reflection

Enhancing this artifact gave me a better understanding of how these small software improvements can increase its quality significantly. As the old ContactService application met my assignment requirements in CS 320, reviewing the code helped me find opportunities to make it more practical and secure. Adding search functionalities required me to think about how data was stored and retrieved while strengthening the existing validation reinforced the importance of preventing invalid data from being entered. One challenge I had faced was implementing enough tests to validate each enhancement I had made is working as intended and that the strengthened validation is throwing exceptions when needed.

Enhancement Three - Databases

Enhancement Summary

Enhancement Original Limitation Enhancement Implemented
Increased Validation Security The original login system stores user passwords directly in the database and does not provide stronger protections against duplicate usernames. Improved login security by implementing password hashing and strengthening validation to prevent duplicate usernames from being stored in the database.
Inventory History The original inventory application uses a basic CRUD system and does not keep a record of changes made to inventory items. Added an inventory history system that records changes made to products, including what product was changed, the amount changed, and when the change occurred.
Inventory Categories Products in the original application are not organized into categories, making it more difficult to group and manage different types of inventory. Added product categories such as food, electronics, and clothing. This expands the database structure and provides a more organized way to manage inventory information.
