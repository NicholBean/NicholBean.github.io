Artifact One - Contact Service

Download Contact Service Artifact

Artifact Narrative

Description

My ContactService assignment was from my CS 320: Software Test Automation course. It was originally created to operate a simple CRUD (Create, Read, Update, and Delete) management system to manage a variety of contacts. This application was able to receive inputs from the user, put them through a validation system to see if they're acceptable, and add them to a single hashmap that can be editted through CRUD methods.

Justification

I chose this artifact to be included in my ePortfolio as it was an assignment I had initially struggled with creating on Eclipse due to issues with the application itself. While the original artifact already has a simple CRUD management system, its first enhancment has many potential components in demonstrating my skills in software development with practices such as validation methods and modifying java classes. To improve this artifact, my first enhancement was the validation logic for the Contact class by adding stronger checks for invalid or null input for all varaibles such as names and addresses, ensuring phone numbers contain only ten digits, and improving duplicate data prevention within the ContactService class. My second enhancement was implementing a multi-index data structure by adding additional HashMap indexes for first names, last names, and phone numbers. These indexes allow the application to retrieve contacts directly instead of searching through every stored contact.

Reflection

Enhancing this artifact gave me a better understanding of how these small software improvements can increase its quality significantly. As the old ContactService application met my assignment requirements in CS 320, reviewing the code helped me find opportunities to make it more practical and secure. Adding search functionalities required me to think about how data was stored and retrieved while strengthening the current validation reinforced the importance of preventing invalid data from being entered. One challenge I had faced was implementing enough tests to validate each enhancement I had made is working as intended and that the strengthened validation is throwing exceptions when needed.

Enhancement Two - Algorithms and Data Structures

Enhancement Summary

Enhancement Original Limitation Improvement Implemented
Multi-Index Data Structure The original application relied primarily on the contact ID to locate contacts. Searching for a contact using information such as a first name or last name would require searching through the stored contacts. Added and maintained additional HashMap indexes for contact ID, first name, last name, and phone number. These indexes allow the application to locate contacts more efficiently using different search criteria.
Search Performance Searching through the contact collection for different attributes could require examining multiple contacts before finding a match. Improved search operations by allowing the application to access contacts through the appropriate index rather than repeatedly searching through the entire collection.

Artifact Two - Inventory Application

Download Inventory Application Artifact

Artifact Narrative

Description

My InventoryApp was a project made for my CS 360 course, Mobile Architecture and Programming. Out of the options I was given, I made an inventory app that was capable of using a password-protected login system, CRUD operations for inventory management, and has a notification system when an item's stock is running low.

Justification

This artifact was selected to demonstrate my skills in another application that uses a different platform like Android Studios. I specifically chose my inventory app because I knew there were a lot of improvements that I could make to showcase my enhanced skills like strengthening password protection with a hashed encryption and an inventory system that monitors changes made to an item.

Reflection

Enhancing my inventory application gave me a better understanding on how databases are utilized and expanded to support more realistic features on current apps. While the original application met its requirements for the course by creating a simple login system, basic CRUD management, notification system, I learned how to add additional database tables and stronger validation that can improve its functionality.


Enhancement Three - Databases

Enhancement Summary

Enhancement Original Limitation Improvement Planned/Implemented
Increased Validation Security The original login system stores user passwords directly in the database and does not provide stronger protections against duplicate usernames. Improved login security by implementing password hashing and strengthening validation to prevent duplicate usernames from being stored in the database.
Inventory History The original inventory application uses a basic CRUD system and does not keep a record of changes made to inventory items. Added an inventory history system that records changes made to products, including what product was changed, the amount changed, and when the change occurred.
Inventory Categories Products in the original application are not organized into categories, making it more difficult to group and manage different types of inventory. Added product categories such as food, electronics, and clothing. This expands the database structure and provides a more organized way to manage inventory information.

Skills Demonstrated

  • Database Design: Improved the structure of the inventory application's databases by expanding how user, inventory, history, and category information can be stored and organized.
  • Secure Data Storage: Applied security practices such as password hashing to reduce the risk of storing sensitive user information in an insecure format.
  • Data Integrity: Strengthened validation and database management practices to help prevent duplicate usernames and maintain accurate inventory records.
  • Database Expansion: Increased the complexity of the original application by incorporating inventory history and product categories into its database design.
  • Problem Solving: Identified limitations in the original inventory application and designed database improvements that provide more realistic and useful inventory management functionality.
